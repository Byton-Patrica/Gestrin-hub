# 架构决策记录

日期：2026-10-18。以下为拟实施决策，尚未有代码或性能证据。

## ADR-001：Android 原生主应用

采用 Kotlin、Jetpack Compose、Room；Flow 提供状态，DataStore 保存简单设置。原因：Android 文件授权、生命周期与自适应窗口是主应用核心。代价是其他操作系统以后需另建客户端。工具链版本在创建工程时核实固定。

## ADR-002：外部运行器优先

主应用负责游戏库和调度，运行器负责模拟、容器和实际执行。首期用静态注册的适配器实现，避免下载任意可执行插件。具体 Intent 只在适配器内构建；外部入口缺乏证据时返回不支持，不能猜参数。

代价：初始化、游戏安装和部分配置在运行器内完成，无法统一控制所有界面、存档和日志。只有主页跳转不算完成指定游戏启动。未来若需要桥接组件，单独提出版本化协议及许可证审计。

## ADR-003：存储与授权是领域约束

GameSource 保存 URI、来源类型、授权状态和可选项目根目录，避免把所有来源强制转换成本地路径。采用用户选择器与最小文件授权；Hub 的授权不自动等于运行器有权限。目录游戏保留相邻资源语义，跨应用共享必须在候选运行器上实测。

Room 迁移需保留用户编辑、来源和运行器绑定。删除库条目不删除游戏。扫描在后台线程进行，支持取消和批量写入；大型目录采用增量扫描，完整哈希仅按需计算。

## ADR-004：状态与证据分离

LaunchAttempt 保存计划、交接和错误；CompatibilityReport 保存实测结果。二者不可混用。报告关联游戏版本、运行器版本/哈希、设备、Android、GPU/驱动和设置。报告状态建议为未测试、无法启动、能启动、可交互、通过本次测试；不提供全局“永久兼容”布尔值。

## ADR-005：本地 AI 提供受限建议

规则优先；日志是待分析数据，包括日志内的自然语言命令，不赋予执行权限。模型只输出结构化建议、证据引用和不确定性；没有外部应用配置写权限。诊断和导出支持脱敏及用户预览，不默认联网。选型取决于参考设备的峰值内存、延迟和错误样例质量评估。

## ADR-006：开放源码与运行器依赖分别管理

主项目拟采用 Apache-2.0，正式 LICENSE 在公开发布前确定。每个运行器保留来源、版本、许可和能力证据；不因进程隔离就推定不受任何条款约束。默认通过官方入口引导安装，任何二进制再分发或源码借用另做锁版审计。

实现更新：已加入 Apache-2.0 LICENSE 与 NOTICE，首个工程使用单 app 模块的包边界；偏好暂使用 SharedPreferences。新增要求明确 APK 不带运行器与兼容环境，按需下载采用 Android DownloadManager，校验后通过系统安装器安装。未知来源授权被拒后停止自动跳转；仅当前台且用户安装请求仍有效时才交接安装。运行器内部依赖在其自身应用中管理。

## 模块边界

| 模块 | 职责 | 不得承担 |
| --- | --- | --- |
| app | 装配、导航、生命周期 | 运行器私有参数细节 |
| core:model | 实体、能力与结果类型 | Android UI、数据库实现 |
| core:data | Room、仓储与迁移 | 启动外部 Activity |
| core:storage | SAF、来源访问、授权检查 | 猜测私有路径 |
| core:runner | 安装检测、版本匹配、五类适配器 | 把交接报告成可玩 |
| core:designsystem | 组件、主题和动效 | 游戏数据业务规则 |
| feature:library | 游戏库、详情、导入交互 | 直接拼装运行器参数 |
| feature:runner | 运行器中心、引导 | 自动操作未验证配置 |
| feature:diagnostics | 日志、规则、可选本地模型 | 任意命令执行 |
